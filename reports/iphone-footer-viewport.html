iPhone Score footer — visual viewport correction

Baseline cdb851c, including completed Hymn 201 cleanup and Hymn 223 fix 2427916. This change concerns shared footer geometry only. Physical Safari/PWA acceptance remains pending.

Cause and measured reproduction

In the reduced visual-viewport simulation, fixed bottom:0 anchored the footer to the 874px layout viewport even though the visible bottom was 650px. Existing safe-area padding protected the home-indicator region inside the footer but could not compensate for the separate 224px browser obstruction. Original, Transpose, Melody and Lyrics all reproduced the same displacement. This demonstrates the failure mechanism; physical browser-chrome behavior still requires confirmation on the user's iPhone.

Implementation

  • footer-viewport.js compares the visible bottom (visualViewport.offsetTop + height) with the unshifted fixed-footer anchor. A shared CSS custom property moves both Score and Lyrics footers above any measured obstruction. It also handles a browser already positioning fixed elements at the visible edge, avoiding a second lift.
  • Enabled at phone widths, plus short coarse-pointer landscape geometry. Tablet/desktop controls retain their previous positioning. Window resize/orientation and visual-viewport resize/scroll are coalesced through requestAnimationFrame. Pinch magnification does not request a new engraving.
  • Home-indicator padding remains intact. Dynamic obstruction is an outer offset; safe padding remains inside the footer. --playing-bar-height reserves the toolbar plus obscured region, excluding safe padding, which existing consumers add once. In the 402×874 / visible650 case it is 326px: 102px toolbar + 224px obstruction.
  • Phone available score height uses the actual footer top. At safe0 the structured budget is 437px; at safe34 it is 403px. PDF fitting uses the same visible footer boundary. Existing margins, minimum sizes, spacing profiles and pagination policy remain unchanged.
  • The structured cache includes available phone height, and resize checks compare that budget even when innerHeight is unchanged. Returning to the same geometry recovers the same engraving and page grouping. No repeated engraving occurred after geometry settled.
  • The page/scroll indicator already clamps to the footer top and now follows it. Touch gestures, defaults and saved navigation preferences are unchanged.
  • Existing URL-gated layout diagnostics now include toolbar/control bounds, obstruction inset and reserved footer footprint for physical follow-up.
